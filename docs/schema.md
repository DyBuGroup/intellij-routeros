# RouterOS schema

Completion, documentation and the annotator use a generated description of the RouterOS
command tree. One schema per MikroTik release channel is bundled as
`src/main/resources/schema/routeros-<version>.json.gz`, listed in `schema/index.json`, and treated
like a lockfile: generated, reviewed, committed.

| Channel | Source of the version | Docs used |
|---------|----------------------|-----------|
| stable (default) | `https://upgrade.mikrotik.com/routeros/NEWESTa7.stable` | `manual.mikrotik.com/docs/<major.minor>/llms-full.txt` |
| long-term | `…/NEWESTa7.long-term` | same, for its version |
| development | `…/NEWESTa7.development` | the unversioned manual when it documents that version |

A project uses the version chosen in *Settings → Languages & Frameworks → RouterOS*; *Automatic*
takes the connected router's major.minor version if it is bundled, otherwise the newest bundled
version not newer than the router, otherwise stable.

## Sources

| File | Origin |
|------|--------|
| `routeros-7.26.json.gz` | Generated by `tools/schema-extractor` from the official CLI reference (`https://manual.mikrotik.com/llms-full.txt`, one request; individual pages are the same Markdown) |
| `overrides.json` | Hand-written patches merged by the extractor (`nodes.<path>` fields replace generated ones) |
| `builtins.json` | Hand-maintained: `:` script commands, common commands (`add set print …`), print parameters, entry properties (`comment disabled copy-from place-before`), universal arguments (`numbers as-value once …`) |

## Regenerating

```
./gradlew :tools:schema-extractor:run --args="--channels"        # all channels, writes index.json
./gradlew :tools:schema-extractor:run --args="--version 7.26"    # one version
```

The **Update RouterOS schemas** GitHub workflow runs `--channels` monthly and opens a pull request.

Options: `--source URL|FILE` (HTTPS only, or a local file), `--out`, `--overrides`,
`--cache DIR` (default `build/schema-cache/<version>`), `--report`, `--refresh`.
Behind a proxy pass `-Dhttps.proxyHost=… -Dhttps.proxyPort=…` via `JAVA_OPTS`, or download
the file yourself and use `--source`.

The extractor writes a report to `tools/schema-extractor/reports/schema-report-<version>.md`
with counts, the diff against the previous schema and type strings it did not understand.

## Format (version 1)

```json
{
  "format": 1, "version": "7.26", "source": "…",
  "nodes": {
    "ip/address": {
      "kind": "dir",                       // dir (list menu) | settings (singleton menu) | cmd
      "doc": "Markdown description",
      "package": "…", "syscap": "…", "conditions": "…",
      "args":  [ { "n": "interface", "t": "iface_enum", "d": "…", "m": 1, "u": 1, "x": 1, "s": "syscap" } ],
      "ro":    [ … read-only arguments … ],
      "flags": [ { "n": "X", "t": "disabled", "d": "disabled" } ]
    }
  }
}
```

`n` name, `t` raw type string from the docs, `d` description, `m` mandatory, `u` can be
unset with `!`, `x` deprecated. Intermediate menus without their own page (for example `ip`)
are created implicitly when the tree is built.

## Type language

`t` strings are parsed lazily by `ValueType.parse` (shared with the extractor) into
`bool`, `num [a..b]`, `enum (a | b)`, `iface_enum`, `ipAddr`, `ipPrefix`, `time`, `ubit (…)`,
`multi { … }`, `super { !, x: T }` (negatable), `alt { … }`, `composite { … }` and more.
Anything not understood becomes `Unknown` and is never reported. Enums listing fewer than three
values are treated as open (`enum (all) { all:0 }` documents special values next to runtime
names).

## Runtime

`RosSchemaService` (application service) loads the bundled schema on first use.
`RosSchema.resolveCommand(path)` splits a resolved path into menu and command word; standard
commands depend on the menu kind (`dir` → `add set remove print …`, `settings` → `set print
get export …`). Warnings derived from the schema are always weak warnings.
